### 1. Оргчасть (коротко)

- Предмет не про «стать ML-инженером» и не про «выучить Unity».
- Цель семестра: **показать разные виды ИИ + сделать рабочие мини-демо**.
- Полигон: **web** (основной) + **Godot 2D** (назвать, без установки Godot на лекции).
- Инструменты в РФ: DeepSeek / Qwen / GigaChat.



### 2. Три вида ИИ (нарисовать на доске / слайд)

На доске заголовок можно сказать так: *«ИИ в играх бывает разный. Мы будем трогать три вида.»*

```
1. Классический game AI     → поведение врагов, путь, «ум» без нейросети
2. Генеративный контент     → текст, картинки, уровни, ассеты
3. LLM и агенты             → диалоги, копилот в IDE, помощь в дизайне
```

Для каждого вида — **один** бытовой пример:

1. Гоблин патрулирует → видит игрока → бежит / атакует (состояния).
2. ИИ нарисовал концепт меча / написал 10 квестов.
3. Ты в Cursor просишь «напиши функцию коллизии» или NPC отвечает через API.

Фраза-якорь: *ИИ в игре ≠ обязательно нейросеть.*

**Важно:** на одной лекции не смешивать виды без ярлыка — всегда говорить: «сейчас про классику» / «сейчас про LLM».



### 3. Примеры «где это уже есть»

Коротко, по 1 минуте на пункт (без разборов кода):

- Враг в платформере / шутере — FSM / деревья решений  
- Навигация NPC по карте — pathfinding  
- Рогалики — ProcGen (процедурная генерация) уровней  
- Современные эксперименты — LLM-диалоги (и почему это хрупко)

Не уходить в Unity/Unreal.

### 4. Правила курса и честности

- ИИ **разрешён и ожидаем** — предмет про него.
- Сдавать нужно умение: **объяснить**, что получилось; указать, где помог ИИ.
- В GDD обязателен блок **«Что сделал ИИ / что изменил я»**.
- Запрещено: сдавать то, что не можешь объяснить; выдавать вывод модели за «я сам придумал механику», если не правил.



### 5. Живое демо (обязательно)

На проекторе один чат (лучше DeepSeek или то, что стабильно открывается).

**Сценарий демо (≈15–20 мин):**

1. Плохой промпт: «Придумай игру» → показать водянистый ответ.
2. Хороший промпт (заранее в буфере):

```text
Ты — геймдизайнер мини-игр.
Составь короткий GDD (Game Design Document) ОДНОЭКРАННОЙ 2D-игры на 5–10 минут геймплея.
Без кода, без лора «на роман», только механика по структуре ниже.

Ограничения:
- жанр: top-down или платформер (выбери один)
- один игрок, один тип врага, без мультиплеера
- без сетевого кода
- механика должна быть реализуема студентом 2 курса за 2–4 практики

Выдай строго структуру:
1. Название
2. Пич в 1 предложение
3. Цель игрока
4. Управление
5. Враг: поведение в 3–5 пунктах (как конечный автомат)
6. Победа / поражение
7. Что можно добавить позже (макс. 3 пункта)
```

1. Одна итерация: «Упрости врага до 3 состояний: patrol / chase / attack».
2. Показать готовый эталон (или сохранить ответ в файл на глазах): [examples/demo-gdd-01-guard.md](./examples/demo-gdd-01-guard.md) — артефакт = файл, не скрин чата. Для разбора «фоновое состояние ≠ FSM» — второй эталон: [examples/demo-gdd-02-sigil.md](./examples/demo-gdd-02-sigil.md).

Сообщение студентам: *на практике вы сделаете своё, не копируя мой пич.*

Фраза с доски (если спросят про ChatGPT): см. [lecture/lect-01-faq.md](./lecture/lect-01-faq.md) — «Чем классический game AI отличается от ChatGPT?»

## Пара 2 (1,5 ч) — Сетап + GDD одноэкранной игры с LLM



### Цель пары

У всех работает хотя бы **один** LLM-чат; заведён шаблон сдачи (`day01-gdd.md`); собран **свой** одностраничный дизайн мини-игры итерациями с LLM.

### Результат к концу пары (сдача дня 1)

- [ ] Аккаунт / доступ: DeepSeek **или** Qwen **или** GigaChat (что удалось)  
- [ ] Папка курса на диске, например `ai-games/day01/`  
- [ ] `day01-gdd.md` — заполненный шаблон (в т.ч. блок «ИИ / я»)
- [ ] Устное (выборочно 4–6 человек): *пич + 3 состояния врага за 1 минуту*

Критерий «зачтено»:

- Есть одноэкранный мир (не MMO, не открытый мир)  
- Враг описан как **состояния**, не «он умный»  
- Есть блок «что ИИ / что я»  
- Студент может объяснить без чтения всего файла целиком

Не требуется: код, спрайты.

### Ход пары


| Мин   | Что делаем                                                             |
| ----- | ---------------------------------------------------------------------- |
| 0–15  | Чеклист доступа: кто чем зашёл; запасной вариант (второй сервис)       |
| 15–25 | Шаблон `day01-gdd.md` (раздать готовый текст)                          |
| 25–35 | Мини-упражнение: 2 промпта «плохой / хороший» на тему *название + пич* |
| 35–55 | Итерация 1: полный GDD по шаблону (промпт из лекции, свой жанр/тема)   |
| 55–70 | Итерация 2: «сожми до одноэкранности»; враг строго 3 состояния         |
| 70–85 | Правки человеком вручную (обязательно хоть что-то переписать самому)   |
| 85–90 | Сдача файлов / мини-круг: пич + 3 состояния врага                      |




### Шаблон `day01-gdd.md` (раздать)

```markdown
# Название

## Пич (1 предложение)

## Цель игрока

## Управление

## Враг (состояния)
- patrol:
- chase:
- attack:

## Победа / поражение

## Что сделал ИИ / что изменил я

## Модель и дата
```



### Промпты-помощники (раздать как шпаргалку)

**Упростить объем:**

```text
Вот мой GDD:
---
{вставить}
---
Вырежи всё, что нельзя сделать за одну встречу (2 пары) студенту 2 курса.
Оставь одноэкранную игру. Ответ — только обновлённые секции шаблона.
```

**Враг как FSM:**

```text
Опиши врага только как конечный автомат:
состояния: patrol, chase, attack.
Для каждого: условие входа, что делает каждый кадр/тик, условие выхода.
Без лишней прозы.
```

**Проверка реализуемости:**

```text
Список из 5 технических задач, которые нужно будет запрограммировать
для этой игры (движение, коллизии, …). Без кода.
```
