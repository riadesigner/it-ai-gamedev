## Чем классический game AI отличается от ChatGPT?

**Короткий ответ**


|                   | Классический game AI                                        | ChatGPT (и похожие LLM)                                       |
| ----------------- | ----------------------------------------------------------- | ------------------------------------------------------------- |
| **Что это**       | Алгоритмы и правила, которые **автор игры написал заранее** | Большая языковая модель: предсказывает следующий токен текста |
| **Где живёт**     | Обычно **внутри игры**, каждый кадр/тик                     | Обычно **снаружи** (API/чат) или отдельный сервис             |
| **Как «думает»**  | По правилам: «если видит игрока → chase»                    | Вероятностно: «какой текст похож на хороший ответ»            |
| **Задача в игре** | Поведение: враг, путь, решения                              | Текст, идеи, диалоги, помощь с кодом                          |
| **Контроль**      | Предсказуемо, тестируется                                   | Может врать / плыть; нужен fallback                           |
| **Интернет**      | Не нужен                                                    | Часто нужен                                                   |


**Аналогия:** классика — светофор и ПДД; ChatGPT — умный советчик по телефону (сам руль не крутит, пока вы не встроите ответ в код).

**Фраза курса:** «ИИ в играх» ≠ обязательно нейросеть. Гоблин с тремя состояниями — уже game AI.

**Паттерн:** классика рулит поведением каждый кадр; LLM (если нужен) даёт редкий текст, не «мозг врага на каждый тик».

## Что такое конечный автомат?

**Короткий ответ**

Конечный автомат (FSM, ) — объект в **одном** из заранее известных **состояний** и чёткие правила **переходов** между ними.

Враг не «думает обо всём сразу». Он сейчас в `patrol`, и только из него может перейти в `chase`, если увидел игрока.

Пример:

- состояния: `patrol` → `chase` → `attack` (и обратно по условиям)
- в каждом состоянии — своё поведение («что делаю сейчас»)
- переход — условие («когда меняю режим»)

**Аналогия:** светофор — только красный / жёлтый / зелёный, не «чуть-чуть зелёный».

**На курсе:** основа классического game AI (день 1 в GDD врага; реализация в М2).

**Частая ошибка:** навалить 15 состояний и запутать переходы. Для учебных врагов хватает **3**.

---

## Что значат patrol → chase → attack?

Это не «магические термины движка», а обычные **английские названия режимов врага**. Их можно было бы назвать по-русски: патруль → погоня → атака.


| Состояние  | По-русски | Что делает враг                                           | Типичный переход дальше                                         |
| ---------- | --------- | --------------------------------------------------------- | --------------------------------------------------------------- |
| **patrol** | патруль   | Ходит по маршруту / стоит на месте, «смотрит» окрестность | Увидел игрока → **chase**                                       |
| **chase**  | погоня    | Бежит за игроком                                          | Подошёл близко → **attack**; потерял из виду → снова **patrol** |
| **attack** | атака     | Бьёт / стреляет / наносит урон                            | Игрок отбежал → снова **chase** (или **patrol**)                |


**Зачем три, а не одно «злой враг»:** так проще программировать и балансировать — в каждом режиме разный код (скорость, анимация, урон).

**Картинка в голове:** охранник в коридоре → заметил нарушителя → догнал → ударил.

На курсе этот набор — учебный стандарт для первого FSM; можно заменить на `idle / flee / hide`, смысл тот же: мало режимов + ясные переходы.

## LLM-чат — это?

**Короткий ответ**

**LLM** (Large Language Model) — большая языковая модель: программа, обученная на огромном количестве текста, которая умеет продолжать и порождать текст «по смыслу» (ответ на вопрос, код, диалог, план).

**LLM-чат** — удобная оболочка вокруг такой модели: вы пишете сообщение → модель отвечает → можно уточнять в том же диалоге (история сообщений).

Примеры интерфейсов: ChatGPT, DeepSeek Chat, Qwen, GigaChat, чат в Cursor.


| Термин | Простыми словами                    |
| ------ | ----------------------------------- |
| LLM    | «мозг», который генерирует текст    |
| Чат    | окно переписки с этим мозгом        |
| Промпт | ваш запрос / инструкция             |
| Модель | конкретный «мозг» (DeepSeek, Qwen…) |


**Не путать:** LLM-чат ≠ классический game AI. Чат помогает писать дизайн и код; враг в игре обычно живёт на FSM/алгоритмах (см. вопросы выше).

**На курсе:** день 1 — GDD через LLM-чат; дальше — копилот в IDE; позже — API той же идеи «внутри» игры для реплик NPC.

## Что означает создать GDD через LLM чат

**Короткий ответ**

**GDD** (Game Design Document) — короткий документ «как устроена игра»: название, цель, управление, враг, победа/поражение. Не код, а **дизайн на бумаге** (у нас — файл `day01-gdd.md`).

**GDD через LLM-чат** — вы не пишете всё с нуля в одиночку, а:

1. Открываете чат (DeepSeek / Qwen / GigaChat…)
2. Даёте промпт с ограничениями (одноэкранная игра, 3 состояния врага…)
3. Получаете черновик → правите → снова просите упростить
4. Итог сохраняете в свой файл GDD и отмечаете в блоке «Что сделал ИИ / что изменил я»

Это упражнение дня 1: показать ИИ как помощника геймдизайнера, ещё до кода и Godot.

**Не путать:** GDD — описание игры; LLM-чат — инструмент, которым черновик набросали.

## LLM-диалоги (и почему это хрупко)?

**Короткий ответ**

**LLM-диалог** — NPC в игре говорит не по заготовленному скрипту, а **генерирует реплику через LLM** (обычно API: отправили контекст → получили текст → показали в UI).

Классика: дерево диалогов / таблица реплик — автор написал все варианты, игрок выбирает или видит фиксированные строки.  
LLM-диалог: модель **импровизирует** на каждый вопрос.

**Почему «хрупко»** — система легко ломается в продакшене:


| Риск                  | Что происходит                                                                 |
| --------------------- | ------------------------------------------------------------------------------ |
| **Непредсказуемость** | NPC может выдумать квест, сломать лор, ответить не по теме или «выйти из роли» |
| **Галлюцинации**      | Уверенно врёт факты о мире игры                                                |
| **Латентность**       | Ответ 1–5+ секунд — диалог чувствуется «тормозным»                             |
| **Сеть / API**        | Нет интернета, лимит, падение сервиса → NPC молчит                             |
| **Стоимость**         | Каждая реплика = деньги / лимит токенов                                        |
| **Безопасность**      | Нужны фильтры: токсичность, спойлеры, личные данные                            |
| **Тестирование**      | Сложно воспроизвести баг: «вчера ответил нормально, сегодня — нет»             |


**Что делает разработчик:** не полагаться только на модель.

- **Fallback** — если API не ответил: заготовленная реплика («Я занят…») или короткий скрипт.
- **Ограничения в промпте** — кто NPC, что можно/не можно говорить, длина ответа.
- **Пост-фильтр** — отсечь длинный или неподходящий текст до показа игроку.

**Аналогия:** классический диалог — актёр читает сценарий; LLM-диалог — импровизация на сцене: может быть ярко, но режиссёр не контролирует каждую реплику.

**Не путать:** LLM-чат для GDD (день 1) — вы **снаружи** игры, черновик дизайна. LLM-диалог — **внутри** игры, реплика NPC в рантайме.

**На курсе:** на лекции 1 — только пример «где уже экспериментируют»; полноценно (API + fallback) — ближе к концу курса. Для учебного врага с FSM диалог через LLM не нужен.

## Что такое деревья решений и чем они отличаются от FSM?

**Короткий ответ**

**Дерево решений** — схема «вопросов да/нет» сверху вниз. Каждый тик (или когда нужно решить) начинаете с корня и спускаетесь по веткам, пока не дойдёте до **листа** — конкретного действия.

Пример:

```
Игрок рядом?
├─ нет  → patrol
└─ да   → Хватает здоровья?
          ├─ нет  → flee (убегать)
          └─ да   → attack
```

**FSM** — вы **уже в состоянии** и сидите в нём, пока не сработает переход.  
**Дерево** — вы **каждый раз заново** спрашиваете условия от корня и выбираете действие.


|              | FSM                                        | Дерево решений                                           |
| ------------ | ------------------------------------------ | -------------------------------------------------------- |
| Память       | «Сейчас я в chase»                         | Обычно без долгой памяти: пересчитали → выбрали действие |
| Удобно когда | Режимы длятся во времени (патруль, погоня) | Много if/else «что сделать прямо сейчас»                 |
| Риск         | Много переходов = «спагетти» состояний     | Глубокое дерево = трудно читать                          |
| На курсе     | **Делаем** (patrol/chase/attack)           | **Обзор** на схеме, без тяжёлой реализации               |


**Аналогия:** FSM — режимы стиральной машины (стирка → полоскание → отжим). Дерево — анкета «куда идти»: ответил на вопросы → получили один совет.

**Не путать с behaviour tree (BT):** в современных играх чаще говорят про **деревья поведения** — родственник идеи, но с узлами Sequence/Selector и статусами running/success/fail. На курсе достаточно фразы: *«есть ещё деревья поведения — сложнее FSM, посмотрим схемой»*. Углублять не обязательно.

## Что такое пич в GDD?

**Короткий ответ**

**Пич** (от англ. *pitch* — «подать идею») — **одно предложение**, которое объясняет суть игры так, чтобы сразу было понятно, во что играют.

Не лор, не список фич. Одна фраза «что делаешь и зачем».

Примеры:

- «Top-down: собери 5 ключей на арене, пока страж в режиме chase не догнал.»
- «Платформер: доберись до выхода, уворачиваясь от одного патрулирующего дрона.»

В `day01-gdd.md` секция «Пич (1 предложение)» — именно это. Если не умещается в одно предложение — объем ещё слишком большой.

## Что такое лор (lore)?

**Короткий ответ**

**Лор** (lore) — **история и мир игры**: кто герои, какой мир, почему враг злой, что за артефакт. Фон и атмосфера, а не правила «как играть».


|         | Лор                                       | Геймплей / GDD-механика          |
| ------- | ----------------------------------------- | -------------------------------- |
| Про что | «почему» и «в каком мире»                 | «что нажимаешь» и «как победить» |
| Пример  | «Дроны охраняют руины старой лаборатории» | «Дрон: patrol → chase → attack»  |


**На курсе:** лор можно чуть-чуть для вкуса, но на дне 1 важнее механика и объем. Красивый лор при раздутом GDD — ловушка; LLM любит писать лор вместо простой игры.

## RPG, рогалик и arcade — в чём отличия?

**Короткий ответ**

Три разных акцента в дизайне:


|              | **RPG**                                | **Roguelike** (рогалик)                    | **Arcade**                             |
| ------------ | -------------------------------------- | ------------------------------------------ | -------------------------------------- |
| **Фокус**    | прокачка персонажа, роль, прогрессия   | повторяемые забеги, риск, рандом           | короткая сессия, реакция, рекорд       |
| **Длина**    | часы / кампания                        | забег за забегом                           | минуты                                 |
| **Прогресс** | постоянный (уровни, скиллы, инвентарь) | часто сгорает при смерти (*permadeath*)    | очки / мастерство игрока               |
| **Пример**   | *The Witcher*, *Persona*               | *NetHack*, *Hades* (часто уже *roguelite*) | *Pac-Man*, многие браузерные мини-игры |


- **RPG** — развитие персонажа и «своя история», не только рефлексы.
- **Roguelike** — процедурная карта/лут + смерть обычно заканчивает забег; *roguelite* — то же, но метапрогресс между забегами остаётся.
- **Arcade** — сразу понятные правила, фокус на тайминг и score, высокая сложность, короткая сессия - 2-3 минуты, мало «сюжета ради сюжета».

**На курсе (день 1):** почти всегда ближе **arcade** (одноэкранная мини-игра). Полноценный RPG или рогалик — слишком широкий объем для GDD на пару.
