# День 1. Первый GDD с помощью LLM

Код игры **не пишем**. Используем ИИ в работе — но финальный текст правите сами и можете его объяснить и защитить.

## Что сдать

Файл `**day01-gdd.md**`

## Что в файле 

GDD - Описание игры с условиями:

- одноэкранная игра, 1 игрок, 1 тип врага;
- враг = состояния `patrol` / `chase` / `attack` (конкретные состояния);

примечение

- объем игры такой, чтобы для ее реализации потребовалось не больше, чем за одну пару (встречу);

- Ваше сравнение ответа от двух LLM



## Как сделать

1. Взять две любые LLM (ниже на выбор или свою).
2. Поработать в каждой с LLM (≥ 3 итерации).
3. Получить в них две разных GDD (по условиям выше)
4. Самим что-то переписать в финале.
5. Взять шаблон `day01-gdd.md (ниже)`и заполнить своим содержанием.



### A. Сетап

- [ ] Чат: DeepSeek / Qwen / GigaChat
- [ ] Редактор: любой + браузерный чат



### B. Примеры промптов

**1. Черновик промпта** — вставьте в LLM, ответ перенесите в `day01-gdd.md`:

```text
Ты — геймдизайнер мини-игр.
Составь короткий GDD одноэкранной 2D-игры на 5–10 минут.
Без кода и длинного лора — только механика.

Ограничения:
- top-down или платформер
- 1 игрок, 1 тип врага, без сети
- реализуемо студентом 2 курса за 2–4 практики

Структура ответа:
1. Название
2. Пич (1 предложение)
3. Управление
4. Враг: 3–5 пунктов как конечный автомат
5. Победа / поражение
6. Что можно реализовать позже (макс. 3 пункта)
```



**2. Пример промта для врага (Враг как FSM):**

```text
Опиши врага только как конечный автомат:
состояния: patrol, chase, attack.
Для каждого: вход, что делает каждый тик, выход.
Без лишней прозы.
```

## Термины


|                |                                       |
| -------------- | ------------------------------------- |
| **GDD**        | как устроена игра (не код)            |
| **Пич**        | одно предложение: во что играют       |
| **Объем игры** | рамки: что делаем сейчас              |
| **FSM**        | режимы врага: patrol → chase → attack |
| **LLM**        | чат с моделью (DeepSeek, Qwen…)       |




## Частые ошибки

- слишком большой дизайн, «умный» враг без состояний;
- сырой ответ чата без правок и без «ИИ / я»;
- не можете объяснить пич и переходы врага.
