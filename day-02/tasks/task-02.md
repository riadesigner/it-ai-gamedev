## Главная идея дня

Практика дня состоит из двух частей. Вот общее описание.  


| Делает человек                                                                                    | Делает ИИ                           |
| ------------------------------------------------------------------------------------------------- | ----------------------------------- |
| Описывает поведение игрока и врага словами                                                        | Пишет и чинит код                   |
| Проверяет в браузере                                                                              | Строит функции и переходы состояний |
| Может найти в коде – **какая функция в коде за что отвечает** (ввод / кадр / коллизия / ИИ врага) | Реализует детали на JS              |


**Не нужно:** писать код.  
**Нужно:** чётко описать *что* должно быть на экране, а ИИ пишет код.

# Подробное описание



## Часть 1 — Игрок и стены (~45 мин)



### Критерии

- Canvas в браузере.
- Игрок двигается **WASD** / **стрелками**.
- ≥ 1 препятствие; игрок **не проходит сквозь** него.



### Шаги

1. Скопируйте [стартер](../examples/starter/index.html) → `day02/index.html`.
2. Промптами: ввод → движение → коллизия со стенами.
3. Проверка в браузере после каждого шага.



### Промпты (примеры) (часть 1)

**Движение:**

```text
Игрок (зелёный квадрат) должен двигаться по полю, пока зажаты WASD или стрелки.
Когда клавишу отпускаю — движение в эту сторону прекращается.
```

**Коллизия:**

```text
Игрок не должен проходить сквозь красные препятствия.
При упоре — останавливается у края, без залипания внутри блока.
```

## Часть 2 — Враг из GDD (~45 мин)



### Критерии

- На сцене есть **враг** (отдельный от стен; в стартере — оранжевый квадрат).
- Работают **3 состояния** из вашего GDD: `patrol`, `chase`, `attack` (как вы описали в день 1).
- Видно на экране:
  - **patrol** — враг патрулирует, пока игрок далеко;
  - **chase** — враг преследует, когда игрок близко;
  - **attack** — короткая «атака» при сближении (остановка, вспышка цвета, пауза — достаточно).
- Враг **не проходит сквозь** красные стены (попросите отдельным промптом, если не сработало).
- В `day02-notes.md` — вставлен **фрагмент GDD про врага**, который отдавали ИИ.

**Упрощение, если GDD сложный:** попросите ИИ упростить до одноэкранной сцены, но **сохранить 3 названия состояний**.

### Шаги

1. Откройте `day01-gdd.md`, скопируйте секцию **«Враг (состояния)»**.
2. Промпт: вставить GDD + описать, что нужно на canvas.
3. Проверить в браузере все три режима (подойти / отойти / подпустить вплотную).
4. Добить баги промптом-симптомом («враг застрял в стене» и т.д.).
5. Обновить **карту функций**.



### Промпты (пример для части 2)

**Главный (из GDD):**

```text
В index.html уже работают: движение игрока, коллизии со стенами, на сцене есть оранжевый враг (пока статичный).

Реализуй поведение врага по моему GDD:
---
{вставить секцию «Враг (состояния)» из day01-gdd.md}
---

Нужно:
- три режима: patrol, chase, attack — как в GDD;
- на экране подписать текущий режим врага текстом (patrol / chase / attack);
- одноэкранная сцена, без спрайтов и звука;
- один файл index.html.

Сначала план из шагов, потом код. Я проверю в браузере.
```

**Если враг не переключает режимы:**

```text
Сейчас враг всегда в patrol / не догоняет / не атакует.
Вот что я вижу на экране: {описать}.
Исправь переходы между patrol, chase и attack по моему GDD.
```

**Стены для врага:**

```text
Враг не должен проходить сквозь красные блоки — так же, как игрок.
```

**Карта функций (финал):**

```text
По index.html составь таблицу основных функций: имя функции → за что отвечает.
Нужны роли: ввод, кадр игрока, коллизии, поведение врага, отрисовка.
```

## Термины


|                          |                                                |
| ------------------------ | ---------------------------------------------- |
| **patrol**               | враг патрулирует, игрок далеко                 |
| **chase**                | враг преследует игрока                         |
| **attack**               | враг атакует вблизи                            |
| **FSM**                  | конечный автомат: режимы и переходы между ними |
| **Классический game AI** | поведение по правилам (не LLM-чат)             |




## Частые ошибки

неправильно → правильно

- Один промпт «сделай всё» → часть 1 отдельно, часть 2 (реализация врага).
- Враг проходит сквозь стены → отдельный промпт про коллизию врага.
- Не видно attack → подойдите вплотную; попросите визуальную паузу/вспышку.
- Не знаете, какая функция за что отвечает → можете найти нужную функцию.

## Справка: промпт для стартера (с нуля)

**Не обязательно.** По умолчанию скопируйте [стартер](../examples/starter/index.html).  
Если хотите собрать каркас сцен **сами через ИИ** — промпт ниже. Дальше те же шаги части 1 и 2.

**Проверка каркаса:** canvas открывается в браузере; на экране зелёный игрок, красные стены, **оранжевый враг** (пока статичный); игрок **ещё не** двигается — это норма.

```text
Создай один файл index.html — минимальная canvas-игра для учебного задания.

Нужно:
- HTML5 Canvas 640×480, тёмный фон страницы, canvas по центру.
- Игрок: зелёный квадрат 28×28, стартовая позиция (80, 80), speed: 4.
- Препятствия: массив obstacles из 2 красных прямоугольников (разные размеры и позиции).
- Враг: оранжевый квадрат 28×28 на (480, 120) — пока статичный, без ИИ.
- Структура кода:
  - объекты player, obstacles, enemy;
  - функции update(), draw(), gameLoop() с requestAnimationFrame;
  - функция rectsOverlap(a, b) для AABB-коллизий;
  - объект keys и TODO-комментарии для keydown/keyup, движения игрока и коллизий.
- Без спрайтов, звука и библиотек. Только vanilla JS.
- Под canvas подпись: «WASD / стрелки — движение (часть 1) · оранжевый враг оживёт в части 2».

Сначала краткий план структуры файла, потом полный код index.html.
```
