# День 2 (встреча 2) — Промпты про поведение + canvas: игрок и враг из GDD

**Модуль:** М1. ИИ как копилот разработчика (+ первый контакт с **классическим game AI**)  
**Задание для студентов:** [tasks/task-02.md](./tasks/task-02.md)  
**Цель встречи:** студенты описывают поведение для копилота, собирают canvas в **две части**: (1) игрок и стены, (2) **враг по GDD дня 1** с состояниями patrol / chase / attack.

**Итог дня (артефакт):** `day02/index.html` + `day02-notes.md` (ИИ / я, журнал промптов, фрагмент GDD про врага).

**Важно:** **вайбкодинг** — человек = ТЗ, ИИ = код, **код не открываем.** На сдаче: playtest (patrol / chase / attack) + прочитать лучший промпт про врага.

**Связь с днём 1:** секция «Враг (состояния)» из `day01-gdd.md` становится промптом для части 2. Это **классический game AI** (FSM), не LLM.

## Какие ИИ-технологии на этом дне и зачем

| Технология / инструмент                      | Роль на дне 2                                        | Зачем студенту                                      |
| -------------------------------------------- | ---------------------------------------------------- | --------------------------------------------------- |
| **Копилот** (Cursor / чат)                   | Код игрока, коллизий, FSM врага по описанию          | ИИ пишет JS; студент проверяет и формулирует ТЗ     |
| **HTML5 Canvas**                             | Полигон                                              | Быстрый результат в браузере                        |
| **Классический game AI (превью)**            | Враг: patrol → chase → attack из GDD                 | Первый «живой» ИИ в игре **без нейросети**          |
| **LLM**                                      | Только как копилот кода, не как мозг врага в рантайме | Не путать виды ИИ (ярлык с доски)                    |
| **Пока не трогаем**                          | Pathfinding, BT, API-диалоги, Godot на этой паре     | День 3 — LLM-идеация; день 4 — gen-спрайты          |

Фраза-якорь: *«Враг думает по правилам из GDD — это классический game AI. Код врага пишет копилот, не ChatGPT внутри игры.»*

### GDD → код врага (обязательный блок, ≈15 мин)

На доске:

```
GDD (день 1)                    Практика (день 2, ч.2)
─────────────                   ───────────────────────
patrol: когда / что делает  →   промпт: «пока игрок далеко — патруль»
chase:  …                   →   «если близко — преследуй»
attack: …                   →   «вплотную — короткая атака»
```

Показать на проекторе: копируем секцию врага из [demo-gdd-01-guard.md](../day-01/examples/demo-gdd-01-guard.md) в промпт → получаем эталон с подписью `враг: patrol`.

**Не углубляться** в теорию FSM — достаточно: «три режима, переходы по условиям из GDD».

## Пара 2 (1,5 ч) — практика в двух частях

### Цель пары

- **Ч.1:** игрок едет, стены держат.  
- **Ч.2:** враг из своего GDD с тремя состояниями; подпись режима на экране; журнал промптов в notes.

### Результат к концу пары

**Часть 1 (~45 мин)**

- [ ] Движение WASD / стрелки  
- [ ] ≥ 1 препятствие, нет прохода сквозь стену  

**Часть 2 (~45 мин)**

- [ ] Враг живёт по GDD (patrol / chase / attack)  
- [ ] На экране видно смену режима (текст `patrol` / `chase` / `attack`)  
- [ ] В `day02-notes.md` — вставлен фрагмент GDD про врага  
- [ ] Журнал промптов (ч.1 + ч.2) в notes  
- [ ] Устно: показать patrol, chase, attack; прочитать промпт про врага  

**Критерий «зачтено»:** обе части работают в браузере; журнал промптов; playtest трёх состояний врага.

**Не требуется:** знание JS, открытие кода, pathfinding, анимации. Счёт, сбор кристаллов, победа/поражение — **домашка** (см. ниже).

### Ход пары

| Мин   | Часть | Что делаем                                              |
| ----- | ----- | ------------------------------------------------------- |
| 0–10  | 1     | Стартер → браузер; оранжевый враг пока статичен — норма |
| 10–25 | 1     | Промпты: ввод + движение                                |
| 25–40 | 1     | Промпт: коллизия игрока со стенами                      |
| 40–45 | 1     | Чек: у всех едет и упирается в стену                    |
| 45–50 | 2     | Открыть `day01-gdd.md`, скопировать секцию врага        |
| 50–65 | 2     | Главный промпт: GDD → поведение врага на canvas         |
| 65–75 | 2     | Проверка 3 режимов; промпты-фиксы симптомами            |
| 75–85 | 2     | Журнал промптов + «ИИ / я» в notes                      |
| 85–90 | —     | Сдача: ч.1 + ч.2, устно про врага                       |

### Промпты для доски

**Ч.1 — коллизия:**

```text
Игрок не проходит сквозь красные блоки. Останавливается у края.
```

**Ч.2 — враг из GDD:**

```text
Реализуй оранжевого врага по этому GDD:
---
{секция «Враг (состояния)»}
---
Три режима patrol / chase / attack. Подпись режима на экране. Один index.html.
```

**Ч.2 — фикс:**

```text
Враг проходит сквозь стены / не переходит в chase. Вот что вижу: …
Исправь по GDD.
```

### Дифференциация

- **Не успели ч.1 к 45 мин:** упростить до одной стены; ч.2 начать с **общего** эталонного GDD преподавателя (не своего).  
- **Средний:** свой GDD, все 3 состояния.  
- **Быстрый:** + враг не проходит стены; + подпись названия игры на экране.

### Типичные сбои (ч.2)

| Проблема | Промпт-симптом |
| -------- | -------------- |
| Враг стоит | «Враг не двигается в patrol — должен патрулировать по GDD» |
| Только chase | «Нет patrol когда игрок далеко» |
| Нет attack | «При сближении вплотную — короткая атака: пауза или смена цвета» |
| Сквозь стены | «Враг тоже не проходит красные блоки» |
| Слишком сложный GDD | «Упрости до одного экрана, сохрани 3 названия состояний» |

### Мини-чеклист сдачи

1. Покажи **patrol** (отойди от врага).  
2. Покажи **chase** (подойди).  
3. Покажи **attack** или объясни, при каком расстоянии должен сработать.  
4. Прочитай **промпт**, которым оживлял врага.

## Что делает преподаватель

**До лекции**

- [ ] Стартер, demo-minimal, demo-enemy — в браузере на учебной ОС  
- [ ] Промпт с фрагментом GDD «Страж арены» в буфере  
- [ ] Напомнить: принести/открыть `day01-gdd.md`

**На практике**

- [ ] **45 мин — жёсткий рубеж:** ч.1 должна работать у большинства  
- [ ] В ч.2 не принимать «враг стоит» — только с видимыми режимами  
- [ ] Ловить путаницу: «ИИ врага» = FSM, не LLM-чат  

**После**

- [ ] Образцы notes с удачными журналами промптов  
- [ ] Если ч.2 провалилась у >50% — на дне 3 дать время добить врага в ч.B, потом идеация

## Домашка (опционально)

- Промптом: враг медленнее / радиус видимости меньше.  
- **Из GDD:** счёт, сбор ключей/кристаллов, жизни, победа/поражение — если не успели на паре.  
- В notes: какой режим из GDD было сложнее всего оживить.
